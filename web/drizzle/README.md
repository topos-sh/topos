# Web-schema migrations

Generated by drizzle-kit; applied eagerly at boot by `app/lib/db/migrate.server.ts` (schema `web`,
ledger `web.__drizzle_migrations`), under an advisory lock so overlapping boots serialize.

**Every migration must be backward-compatible one release back (expand/contract).** The previous
build keeps serving while a new one boots and migrates — any rolling replacement or scaled
deployment overlaps them — and rolling a deployment back runs the previous build against the newer
schema indefinitely. So: additive changes only (new tables, new nullable-or-defaulted columns, new
indexes). A contracting step (drop/rename/retype) ships as its own later migration, once no
deployment still runs code that reads the old shape — and a release that carries one cannot be
rolled back past.
