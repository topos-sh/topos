Every verb that takes a name speaks one grammar. It is **shape-determined**: the shape of what you
typed decides what it means. There is no resolution order to learn, no fallback chain, and the CLI
never asks you which one you meant.

## The table

| You type | Means | Rule |
|---|---|---|
| `code-review` | A bundle in your connected workspaces | No slash = a catalog name. Unique match, or an error listing the candidates |
| `@acme/code-review` | Workspace `acme`'s bundle | **`@` is a workspace, always.** Not connected is a clear error, never a fallback |
| `@acme/channels/backend` | Workspace `acme`'s channel | The `/channels/` path segment marks it |
| `topos.sh/acme/code-review` | Explicit host — **the canonical form** | Works for any host, including self-hosted |
| `topos.sh/acme/skills/code-review` | The skill's page URL | Parses identically — paste a URL from the browser and it works |
| `vercel-labs/skills` | `github.com/vercel-labs/skills` | **A slash without `@` is GitHub, always** |
| `vercel-labs/skills/find-skills` | A subfolder of that repo | |
| `./my-skill`, `../x`, `/abs`, `~/x`, `.` | A local folder | Path shape |

`https://` and `http://` prefixes are stripped before parsing, so a pasted URL and a bare address are
the same thing.

<Tip>
  Canonical references double as web URLs. Open a skill or channel page in the browser, copy the
  address bar, and hand it to `topos add`.
</Tip>

## How the shapes are told apart

A **host** is a dotted token (or `localhost`), optionally with `:port`. That single rule separates
`topos.sh/acme/x` (three segments, host-led → a workspace bundle) from `owner/repo` (two segments, no
host → GitHub).

Names — workspace slugs, bundle names, channel names — are **lowercase letters, digits, and
hyphens**, starting alphanumeric. GitHub owner and repo segments additionally allow `.` and `_`, and
a trailing `.git` is stripped.

## Pins

A pin rides a trailing `@<hex>`, recognized only when the tail is 7–64 hex characters:

```bash
topos add @acme/deploy@9f2c1a8b3d4e5f...   # a workspace bundle: the FULL 64-char digest
topos add vercel-labs/skills#v1.2.0        # a GitHub ref
topos add owner/repo@3aa01e2               # a GitHub commit: 7–40 hex
```

- A **workspace bundle** pin must be the full 64-character version digest. `topos log <skill>` prints
  them.
- A **GitHub** reference takes a 7–40 hex commit.
- A **channel** or a **path** entry takes no pin at all.

## Two banned shapes

<AccordionGroup>
  <Accordion title="A bare @name is invalid syntax">
    ```
    `@name` alone names nothing — a workspace reference is
    `@<workspace>/<skill>` or `@<workspace>/channels/<name>`
    ```

    `@` always introduces a workspace, so `@` with nothing after the slash is meaningless. Pinning
    this as a grammar rule also closes a PowerShell splatting edge case.
  </Accordion>
  <Accordion title="The # sigil is not a channel marker">
    ```
    the '#' sigil is not part of topos references —
    a channel is `@<workspace>/channels/<name>`
    ```

    Channels are addressed by path segment, not by sigil, so that a reference is also a URL.

    One exception, and it is not the grammar: `topos add owner/repo#<ref>` still works, because a
    GitHub source is classified separately. `owner/repo#main` is fine; `@ws#chan` is not.
  </Accordion>
</AccordionGroup>

**Reference-shaped input never falls through.** A token starting with `@` or `#`, a slashless token
carrying `#`, or a host-led token is reference territory — so a typo gets the grammar's typed
refusal, never a confusing "no such file" from some other code path.

## Canonicalization

Manifests always store the **canonical host-qualified form**: `<host>/<workspace>/<name>`, or
`<host>/<workspace>/channels/<name>`. The CLI canonicalizes on write, taking the host from the
session that resolved the reference.

That is why a `topos.toml` read on any machine is never ambiguous — including a teammate's machine
that happens to be logged into a different set of workspaces.

## Disambiguation

A bare name that matches bundles in more than one connected workspace is refused with every candidate
listed as a paste-ready qualified reference. Under `--json` an agent receives the candidates
structurally and can pick from context or ask one question — it never guesses.

The `--workspace <name>` global flag scopes ambient team verbs (a genesis `publish`, `invite`) and
disambiguates a skill delivered from several workspaces.

<Warning>
  `--workspace` does **not** work on `topos logout`, where the workspace is a positional argument
  instead: `topos logout acme`. Passing `--workspace` there is a usage error (exit 2).
</Warning>

## No existence oracle

A name that does not exist and a name that exists but is not visible to you get **one
indistinguishable answer**, at every level, signed in or not. The client phrases status lines only
from what it can see locally — "referenced by this project, not available with your current access" —
never from a server confirmation that something exists.
