**A channel is a named, curated set of bundles.** That is the entire definition.

A channel has no membership roster, no versions, no review ceremony, and no access control. It is a
list of skill references with a name and an audit trail — Gmail labels, not folders. A skill in three
channels is still one skill, delivered once.

```bash
topos add @acme/channels/backend      # this project carries the backend set
topos add @acme/channels/backend -g   # you carry it, on every machine
```

## People carry channels; channels do not hold people

This is the part that most often needs unlearning. There is no "join a channel" operation and no
membership row.

- **A person carries a channel** by referencing it in their profile (`topos add -g @ws/channels/x`)
  or via the browser.
- **A project carries a channel** by referencing it in `topos.toml`.
- The channel page shows an **audience count** — how many people's profiles carry it — never a member
  list.

**"Team" is not a product noun.** A team's set is its channel; a team's people are whoever references
it. An invitation hint can prefill a newcomer's profile with a channel, which is how a lead onboards
someone into a set in one act.

## The default channel is the baseline

Every workspace is born with `everyone`. It is **implicitly part of every member's profile** — the
baseline everyone starts from.

You can subtract individual items from it with an ordinary exclude:

```bash
topos remove noisy-skill -g    # records an exclude in your profile
```

You cannot remove the baseline itself; it mirrors the roster.

## Modes: open and curated

A channel's **mode** governs who may edit its references:

| Mode | Who can add/remove skills |
|---|---|
| `open` | Any member (the default — channels are born open) |
| `curated` | Reviewer or owner |

```bash
topos protect @acme/channels/backend          # describe: tighten to curated
topos protect @acme/channels/backend --yes    # apply
topos protect @acme/channels/backend open --yes   # loosen — owner only
```

<Note>
  **Mode is a CLI-only control today.** The browser shows the mode chip and enforces its consequences,
  but there is no toggle on the channel settings page — use `topos protect`.
</Note>

## The boundary: reach vs. edits

This distinction is worth holding onto, because it explains a behavior that otherwise looks
inconsistent:

- **Edits are protection-gated.** A skill's `open`/`reviewed` protection decides whether your publish
  moves `current` or opens a proposal.
- **Reach is curation-gated.** A channel's `open`/`curated` mode decides whether you can place a
  skill into it.

They are independent. Under a **curated `everyone`**, a member's brand-new publish lands
catalog-only — the version is created, but the placement is withheld and a curator places it. The
describe and the receipt both disclose this rather than failing.

## Creating and curating

Creating a channel is member-level and unconfirmed — an empty named group destroys nothing.

- **Browser:** Channels → New channel. Names are lowercase letters, digits, and hyphens, up to 64
  characters.
- **CLI:** `topos publish <skill> --to <channel>` places a skill into an **existing** channel.

<Warning>
  `publish --to` never creates a channel. Creating one is a curation act that lives in the browser,
  and a missing channel is refused with an explicit message rather than silently minted.

  Two refusals worth recognizing: naming the *workspace* instead of a channel (`--to acme` when your
  publish already lands in `acme`), and naming a channel in a different workspace.
</Warning>

Placements are managed on the channel's Skills tab in the browser — a per-row **Remove**, and an
**Add a skill** picker — or on publish with `--to`.

The channel's **History** tab shows the audit trail: created, renamed, mode changes, skills added and
removed, with refused attempts recorded too.

## Rename and delete

Owner-only, on the channel's settings page.

- **Rename** keeps the channel's skills and history — only the name changes.
- **Delete** stops delivery through that channel. Skills that another channel, a profile, or a
  project manifest still delivers keep flowing; what only this channel delivered leaves machines at
  their next update, with local edits snapshotted first. It is a type-the-name confirmation.

The `everyone` channel is structural: it can be neither renamed nor deleted.

## What channels are not

- **Not access control.** A seat already grants read access to the whole catalog.
- **Not people-groups.** No membership rows, no opt-out rows.
- **Not versioned.** Curation is plain edits with an audit trail — no channel review, no ceremony.
- **Not private.** Private channels are deliberately not built.
