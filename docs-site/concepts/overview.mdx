## The one-sentence model

**An agent gets what the manifests covering its working directory ask for, filtered by what its
person's seats allow.** Nearest manifest wins on a name. The machine itself adds nothing and
subtracts nothing.

## The trust rail

Because there are exactly two inputs, every question about an agent's skills has a short answer:

| Question | Answer |
|---|---|
| Why does this agent have `deploy`? | *This* manifest line asked for it, and *this* seat allowed it. |
| Why doesn't it have `deploy`? | No manifest asks · no seat allows · an exclude line in a manifest you can read. |

`topos status` prints exactly that table, offline. It dials nothing and changes nothing.

```bash
topos status
```

## What the machine does not decide

There is deliberately no machine-level content state. A machine's only variation is **which
workspaces you have logged it into**. There is no per-device subscription list, no device exclusion
table, no opt-out registry, and no server-side record of your project paths — the server never learns
where your repos are.

**Negative state exists in exactly one form: an `exclude` line in a manifest.** Removing something a
broader layer still provides records that line in your layer, and the receipt says so.

## The two motions

<Steps>
  <Step title="Distribute">
    A skill is published to a workspace. Everyone whose manifest asks for it — directly, or through a
    [channel](/concepts/channels) they carry — gets the new bytes at the start of their next agent
    session. Silently, verified byte-for-byte, without touching local edits.
  </Step>
  <Step title="Contribute">
    Someone improves a shared skill. `topos publish` offers it back: landing directly on an open
    skill, or opening a reviewable [proposal](/motions/propose-and-review) on a protected one.
  </Step>
</Steps>

## Where the pieces live

| Piece | What it is | Where it lives |
|---|---|---|
| **Skill (bundle)** | A folder with `SKILL.md` + scripts + docs — the unit of sharing and of trust | The workspace catalog; delivered copies in your agent dirs |
| **Version** | The sha-256 of the bundle's exact bytes. `<skill>@<hash>` pins those bytes | The workspace's byte custody |
| **`current`** | One movable pointer per skill — "what the team is on" | The workspace |
| **Manifest** | The lines asking for skills | `topos.toml` in your repo · your profile on the server · `~/.topos/topos.toml` |
| **Workspace** | The org: one roster, one address, one catalog | The server |
| **Seat** | Membership. Read access to the whole catalog | The workspace roster |
| **Session** | One installation logged into one workspace | `~/.topos/identity/sessions.json` (`0600`) |
| **Channel** | A named, curated set of skills | The workspace |

## Consent: when Topos asks first

Topos asks first when an act **reaches your team, loses local work, or trusts something new**. Those
verbs are two-phase: a bare run *describes* what would change and writes nothing; `--yes` applies it
in one shot.

Everything else — self-scoped acts you can reverse with their inverse command — applies immediately
and prints an **undo-led receipt** naming the command that puts it back.

<Note>
  This is a deliberate scope reduction: no undo beats a wrong one. A receipt offers the inverse
  command only when running it verifiably restores the whole prior state.
</Note>

See [`--yes` and the consent grammar](/reference/json-envelope#consent-and-two-phase-verbs) for the
per-verb table.

## What Topos deliberately does not do

- **No dialect translation between harnesses.** The same bytes go to different paths. A harness is
  *which directories to read and write* plus *when an update check fires*.
- **No second permission system.** Topos guarantees disclosure and integrity — not a sandbox. How
  much a human sits in the loop belongs to your agent harness.
- **No novel cryptography.** Trust sits where your team already puts it: an authenticated principal
  per request, database policy for access, content-addressed versions, audit on every mutation.
  Assurance is *visibility* — a sessions dashboard and one-command revert. See
  [Security model](/reference/security).
- **No relevance AI for distribution.** A human curates a channel; your agent's own skill search does
  discovery *after* delivery.
