Topos has no built-in mail service. You bring an SMTP relay, or you run without mail.

## Arming it

All five, or none — a partial set is treated as unset.

```bash
TOPOS_MAIL_SMTP_HOST=smtp.example.com
TOPOS_MAIL_SMTP_PORT=587
TOPOS_MAIL_SMTP_USER=topos@example.com
TOPOS_MAIL_SMTP_PASS=<secret>
TOPOS_MAIL_SMTP_FROM="Topos <topos@example.com>"
```

<Note>
  **Port 465 means implicit TLS.** Any other port uses STARTTLS negotiation.
</Note>

Restart the app. There is nothing else to configure — the same transport carries every kind of
message the product sends.

## What changes when mail is armed

<Columns cols={2}>
  <Card title="Works either way" icon="check">
    - The claim ceremony
    - Email + password sign-in
    - `topos login` and browser approval at `/verify`
    - Publishing, review, revert, delivery
    - **The entire core loop**
  </Card>
  <Card title="Needs mail" icon="envelope">
    - **Inviting teammates** — the mailbox round-trip *is* the identity proof
    - Password-reset mail
    - Magic-link sign-in (the rung is only added when mail is armed)
    - Address-verification mail
  </Card>
</Columns>

<Note>
  **A rung never advertises a dead door.** Magic link does not appear on the sign-in page unless mail
  can actually send, and the invite form tells you plainly when it cannot:

  > Configure mail (`TOPOS_MAIL_SMTP_*`) to invite your team — the invitation's identity proof is a
  > mailbox round-trip.
</Note>

## Running without SMTP

A pending invitation admits **nothing** when mail is unarmed, so an install with no relay is
effectively single-user until you change something. Two paths:

<Tabs>
  <Tab title="Open registration (recommended without mail)">
    **Settings → General → Registration**, owner-only, single-workspace installs:

    > Open — anyone reaching this origin may create an account

    Then hand out the workspace address. This **disables the invitation proof entirely** — anyone who
    can reach the origin can sign up. Reasonable on an internal network or behind a VPN; think twice
    on a public one.

    The knob does not change what `/login` renders; it changes whether an uninvited sign-up succeeds.
  </Tab>
  <Tab title="Arm a relay">
    Any transactional relay works. This is the path that keeps invitations meaningful, and it is what
    the invitation flow is designed around.
  </Tab>
</Tabs>

## What an invitation mail contains

Three routes, in order, so whoever receives it can use whichever fits:

1. A browser link to the accept page.
2. A paste-block for their agent.
3. `topos login <invite-url>` — enrolled machines accept without a browser at all.

The token travels **only** in the mail. The inviter never sees the link, and the accept is bound to
the invited address.

<Warning>
  An invitation link is a capability URL. A deployment that admits invitations **must** pin
  `TOPOS_PUBLIC_URL` — otherwise a forged `Host` header could re-root a mailed token at somebody
  else's host.
</Warning>

Invitations lapse after 7 days. Re-inviting an address mints a fresh link, kills the old one, and
re-arms the clock — there is deliberately no separate "resend" button.

## No SMTP and a forgotten password

There is a one-shot escape hatch: machine control is the proof.

```bash
DATABASE_URL=<your url> node web/scripts/mint-recovery-code.mjs someone@example.com
```

It prints a single-use code with a 15-minute lifetime, stored only as a hash. Redeem it at
`<origin>/recovery` to set a new password.

<Warning>
  **This script is not in the runtime web image.** Run it from a checkout against the same
  `DATABASE_URL`, or copy it into the container first:

  ```bash
  docker compose cp web/scripts/mint-recovery-code.mjs web:/app/
  ```
</Warning>

## Mail logging

Every send attempt writes one **metadata-only** row: the kind of message, the recipient, the outcome,
and a coarse code. **Never a subject, never a body, never relay text.**

The table is written by the transport and readable by an operator directly. No reader UI ships with
the product.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Invite form says to configure mail | One of the five variables is missing. It is all-or-nothing |
| Magic link missing from the sign-in page | Same — the rung only registers when mail can send |
| "The invitation stands, but the mail didn't send" | The row was created; the relay rejected the message. Invite the address again to resend |
| Invited people land on a dead-token page | The link lapsed (7 days), was revoked, was already used, or a newer invite superseded it |
| Links point at `localhost` | `TOPOS_PUBLIC_URL` is unset or wrong |
