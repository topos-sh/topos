A fresh install mints one workspace and prints **one** setup link. Whoever opens it creates the first
account and becomes the owner.

## What happens on the first boot

<Steps>
  <Step title="Migrations run">
    Both applications migrate their own schema before binding a port. A broken migration crashes the
    boot loudly rather than serving an unmigrated database.
  </Step>
  <Step title="The workspace is minted">
    On the first request, inside one advisory-locked transaction: the workspace row (named
    `TOPOS_WORKSPACE_NAME`, default `team`), its implicit `everyone` channel, and an audit row.
  </Step>
  <Step title="The setup link is printed">
    ```
    → Finish setup: https://topos.example.com/claim?code=…
    ```
    Exactly one line, to the logs. Only `sha256(code)` is ever stored.
  </Step>
</Steps>

<Note>
  While the workspace is **unclaimed**, every boot re-mints and re-prints a fresh code. Once it is
  claimed, nothing further is printed. So a lost link is recovered by restarting the app — before
  anyone has claimed it.
</Note>

## Claim it

```bash
docker compose logs web | grep 'Finish setup:'
```

Open the link. The page reads:

> **Finish setup** — Claim *team*
> Create the first account on this install — it becomes the workspace owner.

Fill in name, email, and a password of at least 8 characters, and press **Claim this workspace**.

- The claim is **single-use by construction** — one atomic update arbitrates any race, and the loser
  gets the same uniform 404 as a wrong code.
- A missing, wrong, or already-spent code renders the ordinary house 404. There is no "invalid code"
  message to probe.
- You land signed in, seated as **owner**.

### Presetting the code for CI or IaC

```bash
TOPOS_SETUP_CODE=<at least 16 characters>   # skip reading the logs
TOPOS_SETUP_LINK_FILE=/var/run/topos-setup  # also append the printed line to a file
```

Mirroring to a file is best-effort and never blocks boot.

## Connect the first machine

```bash
topos login https://topos.example.com
```

A bare origin means *"the workspace that origin addresses"* — exactly right for a single-tenant
install. Approve at `<origin>/verify` and you have a session.

Then publish something:

```bash
topos publish ~/.claude/skills/pr-describe          # describe
topos publish ~/.claude/skills/pr-describe --yes    # apply
```

## Add your team

This is where the shape of your install matters.

<Tabs>
  <Tab title="With SMTP configured">
    The normal path. Invitations work, and the mailbox round-trip is the identity proof.

    ```bash
    topos invite dev@example.com ops@example.com --yes
    ```

    Or use the **Members** page. Each person accepts the mailed link, then runs
    `topos login https://topos.example.com` on their machine and approves it at `/verify`.

    See [Mail](/self-hosting/mail) to arm SMTP.
  </Tab>
  <Tab title="Without SMTP">
    **Registration stays closed by design** — the claim owner is the only account, because there is
    no way to prove control of an address.

    Two options:

    1. **Arm SMTP** and invite normally. Recommended.
    2. **Open registration** on **Settings → General → Registration**:

       > Open — anyone reaching this origin may create an account

       Then hand out the address. This disables the invitation proof entirely, so only do it on an
       origin that is not publicly reachable, or when you genuinely want anyone who can reach it to
       sign up.
  </Tab>
</Tabs>

<Warning>
  The **Registration** panel exists only on a single-workspace install, and it does not change what
  `/login` renders — the "Create an account" toggle is always present. What the knob changes is
  whether an uninvited sign-up **succeeds**.
</Warning>

## Sign-in methods you actually get

The OSS default rung is **email + password**, with no delivery dependency.

- **Magic link** is registered *only when SMTP is armed*. When present it leads the page — "We'll
  email you a sign-in link — no password needed" — and password becomes a quiet secondary link.
- **Social sign-in** (Google and friends) is a composition seam that ships **empty** in the
  open-source build. There is no OAuth self-hosted.

## A sensible first hour

<Steps>
  <Step title="Rename the workspace if you want">
    The slug is renameable in-product later; `TOPOS_WORKSPACE_NAME` only sets the initial value.
  </Step>
  <Step title="Decide the review gate">
    **Settings → General → Review gate.** Off (open) is right for a small team; on makes every
    unpinned skill's publish a proposal. Individual skills can pin their own protection.
  </Step>
  <Step title="Decide the session policy">
    **Session approval** (off by default) makes a member's new login wait for you. **Session expiry**
    (none by default) forces periodic re-login. Neither is required.
  </Step>
  <Step title="Invite one person and watch it land">
    Then open **Settings → Sessions** and confirm their machine reports `current`. That page is how
    you answer "did it reach everyone?" from then on.
  </Step>
  <Step title="Set up backups">
    Before you have anything worth losing. See [Backups](/self-hosting/backups).
  </Step>
</Steps>
