A behavior you receive is prose and code that runs inside your agent. So integrity and disclosure are
the whole point of the tool — and it is worth being exact about which properties you get.

## What is guaranteed

<Steps>
  <Step title="TLS everywhere, and every request is an authenticated principal">
    A signed-in person or a logged-in session. There are no anonymous mutations.
  </Step>
  <Step title="Access is database policy">
    Roster and role rows decide every authorization. **Revocation is a row delete, effective
    immediately** — no cache to expire, no token to wait out.
  </Step>
  <Step title="Versions are content-addressed">
    A version **is** the sha-256 of its bytes. What you pin is exactly what you get, and different
    bytes are never "the same version."
  </Step>
  <Step title="No anonymous writes">
    Every mutation of shared state is attributed and audit-logged — including refused attempts.
  </Step>
  <Step title="Bytes and pointers move only through the server's own lane">
    Policy rows are written by the app under scoped database roles. Enforced by grants, not
    convention.
  </Step>
</Steps>

This is **git/GitHub-level trust**: the grade a team already extends to its source host and CI.
Nothing is invented.

## What is deliberately not built

Absence here is a choice, journaled and revisitable — not an oversight:

| Not built | Why |
|---|---|
| Pointer signing | Assurance is visibility, not cryptography |
| Key pinning | Same |
| Client-side verification of authority | The client verifies *bytes* against the digest it was told; authority is server-side |
| Anti-rollback cryptography | A rollback is a visible, audited, invertible pointer move |
| Per-skill credentials | A seat is read access to the catalog |
| A sandbox for skill contents | Topos guarantees disclosure and integrity, **not** that an approved behavior is safe to run |
| A second permission system | How much a human sits in the loop belongs to your agent harness |

<Note>
  **Assurance is visibility.** The sessions dashboard plus one-command revert is the answer to "did
  the bad thing reach anyone, and is it gone?" — not a cryptographic proof. Optional signing can
  layer on later without a redesign, because versions are already content-addressed.
</Note>

## What Topos does not judge

Topos does not evaluate whether a skill is *safe*. It guarantees:

- the bytes you get are the bytes that were published,
- you can see who published them and when,
- and you can move the pointer back in one command.

It does not guarantee that the script inside is benign. **Review is the control** — that is what
`reviewed` protection, proposals, and the audit trail are for.

Importing from a public GitHub repo is the sharpest edge here: **the source's trustworthiness is
yours to verify.** Topos records provenance and routes every later upstream change through review; it
does not vet the code.

## Integrity in delivery

- The client re-hashes what it fetches and must **reproduce the expected digest** before anything
  lands.
- A reviewer approving a proposal binds the proposal's recorded identity — the digest is re-derived
  from the fetched bytes and must reproduce the proposal's hash. **A tampered server cannot get a
  reviewer to sign over forged bytes.**
- An approval is a compare-and-set against the base the diff was rendered on: if `current` moved,
  the approval is refused rather than landing something unseen.
- Bundle scanning refuses symlinks, non-regular files, `..` traversal, absolute paths, control
  characters, and case-fold or Unicode-normalization collisions.

## Release integrity

Releases are signed with **minisign** and carry **Sigstore build-provenance attestations**.

```bash
shasum -a 256 -c SHA256SUMS
minisign -Vm topos-<target>.tar.gz \
  -P RWRsqhNImLJGum9BdXy1X/p7Dhr+xc0JQTyNPxaGW5emP/K/+828Euav
gh attestation verify topos-<target>.tar.gz --repo topos-sh/topos
```

- `topos self-update` verifies the signature **before** the checksum, and **both are mandatory** — a
  failure is a typed integrity error with no fallback.
- The installer's sha-256 check is **never skippable**; no flag disables it. The signature is
  required to download and verified when `minisign` is present.
- Each signature's trusted comment binds it to one release, so a signature cannot be replayed under a
  different tag.
- Key rotation happens through a transitional release signed with the **old** key that carries the
  new public key.

## Secrets at rest

| Where | What | Protection |
|---|---|---|
| Each machine | `~/.topos/identity/sessions.json` — the workspace-scoped session credentials | Mode `0600`, plaintext. Losing it means logging in again |
| Server | Nothing | The vault is identity-free; the internal bearer arrives by environment, never from disk |
| Server | Claim codes, invitation tokens, recovery codes | Stored **only** as hashes |

At-rest encryption is not implemented. Disk or volume encryption is the operator's responsibility and
the right layer for it.

## Non-oracle answers

A name that does not exist and a name that exists but is not visible to you get **one
indistinguishable answer**, at every level, signed in or not.

- The API answers a uniform 404 shape for "no such thing", "not a member", and "no such bundle".
- The client phrases status lines only from **local file knowledge** — "referenced by this project,
  not available with your current access" — never from a server confirmation.
- Reserved and taken workspace slugs refuse **byte-identically**.
- A dead invitation token renders one constant page naming neither the workspace nor the email.

## Confirmation ceremonies

Ceremonies **confirm; they do not re-authenticate**. A live session plus the role the guard minted is
the authority; the ceremony adds friction proportional to reach.

| Tier | Used for |
|---|---|
| **Type the exact name** | Delete a channel · purge a version's bytes · delete an archived skill |
| **In-place two-step confirm** | Remove a member · change a role · leave · approve/reject/remove a session · roll back · rename · archive |
| **Deliberate but unarmed** | Reject or withdraw a proposal — behind a disclosure, with a mandatory reason |
| **Plain submit** | Policy saves · channel curation · profile edits · approving a proposal (bound by generation) · ending your own session |

Every ceremony keys on an **immutable id** carried in the form, never the URL's mutable name — so a
rename between page load and submit refuses honestly rather than retargeting something else.
