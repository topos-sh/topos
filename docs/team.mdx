A **workspace** is your team: one member list, one address, one catalog of skills. This page
is the team toolkit — who's in, who reviews, which group gets which skills, and whether it
all landed.

<Note>
  Agents distribute skills; **they don't manage people**. `topos invite` is the only roster
  command in the CLI — roles, removal, and leaving are browser acts, deliberately.
</Note>

## Invite people

```bash
topos invite dev@acme.com --yes
topos invite dev@acme.com --channel backend --yes  # with a skill set
```

Owner-only, and the server needs [mail configured](/docs/self-host#mail) — Topos Cloud has
it. Each address gets a single-use link, valid 7 days (re-inviting sends a fresh one). The
mail offers all three ways in: a browser click, a paste-block for their agent, and
`topos login <invite-url>`. Accepting is bound to the invited address; someone without an
account gets one minted on the spot.

Accepting makes them a **member** — raise roles afterwards on the Members page. Nothing
lands on their machines until they run `topos login` there.

## Roles

| Role | Adds |
|---|---|
| **member** | Use skills, publish to open skills, create channels |
| **reviewer** | Approve/reject proposals, roll back, curate curated channels, see the whole fleet |
| **owner** | Invite, set roles, remove people, loosen protection, delete, change settings |

The workspace always keeps an owner: the last one can't be demoted, removed, or leave —
promote someone else first.

## Channels — "this group needs this set"

A **channel** is a named set of skills. Create one in the browser (**Channels → New
channel**), fill it on its Skills tab — or at publish time:

```bash
topos publish deploy --to backend --yes
```

People carry a channel with one command:

```bash
topos add @acme/channels/backend -g  # follows you to every machine
topos add @acme/channels/backend     # or pinned into this repo
```

Channels reference, they don't own — a skill in three channels is one skill, delivered once.
Any member may curate an open channel; make one curated (reviewers and owners only) with
`topos protect backend --yes`. Use the plain channel name with `protect`.

**`everyone`** is the built-in baseline: whatever is placed there reaches the whole team with
no steps — it's where a new skill lands by default. Individuals can opt out of single items
with `topos remove <skill> -g`; the channel itself can't be deleted.

## Did it land?

**Settings → Sessions** answers "is everyone current — did the rollback reach?" Every
logged-in machine is listed with its per-skill state (current or behind), when it last
reported, and a freshness chip. Machines report when an agent runs, so an idle laptop reads
*stale* — unconfirmed, not wrong. Owners can approve, reject, and remove sessions there;
people end their own with `topos logout`.

## Removing access

- **Remove a member** (owner, Members page): their seat and their logins in this workspace
  end together. Local copies stay theirs — removal stops future delivery; it never deletes
  files on someone's machine.
- **Remove one machine** (owner, Settings → Sessions): ends exactly that login.
- **Leave** (anyone, own seat): ends all of your own machines' access.

## Policy

**Settings → General**, owner-only — each knob shows who last changed it:

| Setting | Default | What it does |
|---|---|---|
| Review gate | off | Every skill change needs review, unless a skill overrides it |
| Staleness window | 7 days | When a machine reads *stale* on the Sessions page |
| Session approval | off | New logins wait for an owner's approval before anything is delivered |
| Session expiry | none | How long a login lasts before the machine logs in again |
| Export skills | — | Every skill at its current version, as one zip |

## Who can see what

A workspace's skill and channel pages answer **only for signed-in members** — anyone else
gets a plain 404, so a URL can't leak what exists.

<Warning>
  Don't hand a skill-page URL to someone outside the workspace as their way in — it 404s for
  them. Send an invitation, or the workspace address for `topos login`.
</Warning>
