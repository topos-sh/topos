Topos knows about 70+ agent harnesses. The directory conventions below are sourced from
[`vercel-labs/skills`](https://github.com/vercel-labs/skills) (MIT). User-scope directories resolve
under `$HOME`; project-scope directories are relative to the directory you run in.

Support tiers are explained in [How harness integration works](/harnesses/how-it-works):
**auto-update** (Topos installs an update trigger) · **delivery** (skills are placed and refreshed,
no trigger installed) · **discover + add** (project-scoped only — Topos can adopt from there, but has
no machine-wide place to deliver into).

<Note>
  Do not see yours? Skills are plain directories, so a harness that reads a skills folder will pick
  up delivered bundles whether or not it is listed here. `topos list` also discovers untracked skills
  in any of these directories, ready to `topos add`.
</Note>

## The shared directory

`~/.agents/skills` is a cross-harness convention. Where a detected harness is known to read it, Topos
places **one** copy there instead of a native copy per harness — so several agents on one machine
share the same bytes.

Coverage is tracked with provenance and **fails closed**: a harness whose support is unknown is
treated as *not* covered and gets its own native copy. Some entries are confirmed by probing a real
build; others come from vendor documentation, and receipts disclose which.
