Five steps. At the end, your team has a shared workspace, one skill in it, and machines that
keep themselves current — no one runs anything to receive updates.

<Steps>
  <Step title="Create a workspace">
    A workspace is your team's shared home for skills: one address, one member list, one
    catalog.

    <Cta title="Create a workspace on Topos Cloud" href="https://topos.sh" />

    Sign up, pick a name, and your team's address is `https://topos.sh/<name>`. You can also
    [self-host](/docs/self-host) the whole product on your own server — then the address is
    your own domain. Already invited by a teammate? The address is in the invitation mail —
    go straight to step 2.
  </Step>
  <Step title="Install the CLI">
    <Columns>
      <Column title="In a terminal">
        ```bash
        curl -fsSL https://topos.sh/install | sh
        ```
      </Column>
      <Column title="Or paste to your agent">
        ```text
        Set up Topos for us: fetch https://topos.sh/agent and follow it. Our workspace: https://topos.sh/acme
        ```
      </Column>
    </Columns>

    macOS and Linux, WSL2 on Windows; no sudo. The agent route also handles the next step for
    you — only the browser approval stays yours to click. Details and verification:
    [Install](/docs/install).
  </Step>
  <Step title="Log in">
    ```bash
    topos login https://topos.sh/acme
    ```

    Your browser opens — click **Approve**. That one click is the whole setup: the
    workspace's skills land on this machine, and from now on updates apply silently at the
    start of each agent session.
  </Step>
  <Step title="Share a skill">
    Point `publish` at any skill folder you already have — for example one in your agent's
    skills directory:

    ```bash
    topos publish ~/.claude/skills/pr-describe
    ```

    A bare `publish` is a preview: it prints exactly what would happen and changes nothing.
    Read it, then apply:

    ```bash
    topos publish pr-describe --yes
    ```

    The workspace now owns the skill — one version history, one current version for the whole
    team, and a page at `https://topos.sh/acme/skills/pr-describe`.
  </Step>
  <Step title="It reaches your team — automatically">
    Nothing for teammates to run: every machine logged into the workspace receives the skill
    at its next agent session (or right away with `topos update`). Bring someone new in:

    ```bash
    topos invite dana@acme.com --yes
    ```

    The invitation mail carries everything they need, including a line to paste to their
    agent.
  </Step>
</Steps>

## From here

- **Edit freely.** Updates never overwrite your local edits. Share an improvement back with
  `topos publish pr-describe -m "Cover stacked PRs" --yes`.
- **Pin skills to a repo.** `topos add pr-describe` inside a checkout writes `topos.toml`;
  commit it and everyone working in that repo gets the same set.
- **Check any time.** `topos status` — offline — lists every skill on this machine, its
  version, and where it comes from.
