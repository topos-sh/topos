Two things decide what an agent has on a machine: what the **manifests** covering its working
directory ask for, and what your **workspace seats** allow. `topos add` edits the asking side and
delivers in the same command. Nothing else decides — and `topos status` names the exact line
behind every skill on disk.

## Ask for a skill

```bash
topos add code-review                 # a bare catalog name, when unique across your workspaces
topos add @acme/code-review           # workspace-qualified
topos add @acme/channels/backend      # a whole channel's set
topos add topos.sh/acme/code-review   # canonical form — a pasted skill-page URL works too
topos add @acme/deploy@<64-hex>       # pinned to exact bytes
topos add ./tools/my-skill            # a local folder, adopted in place — offline, no account
topos add vercel-labs/skills          # GitHub import (a slash without @ is GitHub, always)
```

The shape of what you type decides what it means — `@` always introduces a workspace, a slash
without `@` is always GitHub, a dotted host is the canonical form, a path shape is a local
folder. There is no fallback chain, and an ambiguous bare name is refused with every candidate
listed as a paste-ready reference.

The receipt names the manifest it edited and the undo, then confirms delivery:

```text title="topos add @acme/deploy"
/Users/you/proj/topos.toml: added "topos.sh/acme/deploy" (undo: topos remove topos.sh/acme/deploy)
Adopted 'deploy' @ be8a0ecd6173
```

## Project scope or person scope

<Tabs>
  <Tab title="Project (default)">
    ```bash
    topos add code-review
    ```

    Writes the **nearest `topos.toml`** covering your current directory — the manifest is created
    at the enclosing git root if none exists. **Commit it.** It is the recipe that gives every
    teammate's agents the same set in this repo: anyone who clones and starts their agent
    converges on it, minus anything their seats do not allow.
  </Tab>
  <Tab title="Person (-g)">
    ```bash
    topos add code-review -g
    ```

    Writes your **server-stored profile** for that workspace. It follows you to every machine you
    log in, and it is editable in the browser under **Your skills**. (`-g` with a local path
    writes `~/.topos/topos.toml` instead — a path cannot live on the server.)
  </Tab>
</Tabs>

The manifest file itself is plain TOML, and hand-editing is fully supported — comments and layout
survive:

```toml title="topos.toml"
exclude = [
  "topos.sh/acme/noisy-skill",   # the one form of negative state
]

[skills]
"topos.sh/acme/code-review" = "*"                               # track current
"topos.sh/acme/deploy" = "be8a…full 64-hex…"                    # pinned to a version
"github.com/vercel-labs/skills/skills/find-skills" = "e173b8c"  # external: pinned to a commit
"./tools/my-skill" = "*"                                        # a local folder in this repo

[channels]
"topos.sh/acme/channels/backend" = "*"
```

Layers resolve **nearest first**: this folder's `topos.toml`, then ancestor folders' (a monorepo
walk, like git's), then your per-workspace profile, then `~/.topos/topos.toml`. The nearest layer
that names an item wins whole — so a project can exclude a skill your profile provides, and
`topos status` shows the line that did it.

<Note>
  You do not have to `add` everything. Skills placed in the **`everyone`** channel are implicitly
  part of every member's profile — they arrive on your machines just by being logged in. `add`
  is for pinning a set to a project, following a narrower channel, or pulling in something
  outside the baseline.
</Note>

## Where the bytes land

Delivered skills are placed into the skills directories of the harnesses actually detected on
the machine — `~/.claude/skills/<name>` or the shared `~/.agents/skills/<name>` for person scope,
the project's own agent dirs (`.claude/skills/…`) for project scope. Inside a checkout, every
placement is kept out of commits by one appended line in `.git/info/exclude`:

```text
# topos-managed skills (placed by `topos update`; not committed)
/.claude/skills/code-review/
```

Committed ignore files are never touched, occupied directories are never clobbered, and a
`[placement]` entry in `topos.toml` can pin one project-relative directory for every agent. The
full directory table and placement rules: [Which agents it works with](/docs/harnesses).

## Updates arrive by themselves

Logging in arms a session-start trigger that runs `topos update --quiet` — silent, self-throttled
(default 300 s), and designed never to break a session start: an auth or network blip warns and
exits `0`. Run the same sweep by hand any time:

```bash
topos update              # the full sweep — resolve every layer, land what changed
topos update code-review  # one skill
topos update code-review@a4188e38   # go back to a version's bytes ON THIS MACHINE only
```

```text title="topos update"
code-review  fast-forwarded — now at generation 2
deploy       merged — your draft was rebased onto the new current as @daf50a402585; review with `topos diff deploy`, then publish
Checked 4 managed skill(s): 2 up to date.
```

New bytes are verified against the workspace's `current` digest before anything lands, and
**your local edits are never overwritten** — an update merges around them, and a genuine
conflict freezes the copy with markers and a named way out. Details:
[Review, protect, roll back](/docs/review#when-your-own-edits-are-in-the-way).

## Import from GitHub

```bash
topos add vercel-labs/skills                  # a public repo — no account needed
topos add vercel-labs/skills -s find-skills   # pick one skill from a repo holding several
topos add owner/repo#v1.2.0                   # a tag, branch, or commit
topos add https://github.com/owner/repo/tree/main/skills/deploy
```

The bundle is fetched, **pinned to a commit**, and its provenance recorded:

```text
/Users/you/proj/topos.toml: added "github.com/vercel-labs/skills/skills/find-skills" (undo: topos remove github.com/vercel-labs/skills/skills/find-skills)
Adopted 'find-skills' @ 0cd25bd05d70
Imported from github.com/vercel-labs/skills@e173b8c (skills/find-skills) · MIT
```

The reference keeps the skill's **path inside the repo** (`skills/find-skills` here), so two
skills with the same name in different repos — or in different folders of one repo — never
collide.

Workspace references track `current`; **GitHub references are pinned by default** — there is no
governance rail behind a third-party repo, so the entry behaves like a lockfile line and moves
only when you move it. Re-running `add` with a bumped pin re-imports; an import refuses over
local edits rather than clobbering them.

<Warning>
  A skill is prose and scripts that run inside your agent, and Topos verifies nothing about an
  imported repo's contents. **The source's trustworthiness is yours to verify.**
</Warning>

Once an import is **published to your workspace**, its provenance travels with it, and the
workspace watches upstream: when the source repo moves, the new bytes arrive as an ordinary
**proposal** — external changes always propose, even on an unprotected skill; the outside world
never moves your `current`. A skill's Settings tab (owner-only) shows the upstream link and a
**Check for updates** button. There is also a browser import at `<origin>/skills/import` with a
what-would-land preview.

## Stop receiving

`topos remove` is the exact inverse of `add` — it edits the same manifest and prints the file it
touched with the command that puts it back:

```bash
topos remove code-review        # from this folder's reach
topos remove code-review -g     # from your profile — every machine you log in
```

Two outcomes, and the receipt says which: the line is **dropped** (nothing broader was asking),
or an **exclude line is recorded** because a broader layer — your profile, a channel, the
`everyone` baseline — still provides it:

```text
/Users/you/proj/topos.toml: excluded 'code-review' — a broader layer still provides it, so an exclude line (the one negative state) now withholds it here.
Undo: topos add topos.sh/acme/code-review
```

An exclude is the **only** negative state in Topos — if something is missing, one line in one
readable file explains it, and `topos status` names that line.

Most removes apply immediately with an undo-led receipt. Two cases describe first and want
`--yes`, because loss is real: the copy has **local edits ahead**, or it is **local-only and
never published**, so the delete is permanent. The guard fails toward asking: if the scan cannot
tell whether edits exist, it describes rather than assumes.

Bigger exits, in increasing order:

```bash
topos logout acme        # stop one workspace delivering to this machine — skills and drafts stay, frozen
topos uninstall --yes    # remove topos from the machine — hooks scrubbed, ~/.topos/ deleted,
                         # NOT ONE SKILL BYTE deleted; the binary's path is printed
```

And when the workspace acts — a skill archived or deleted, a channel deleted, your seat removed —
delivery stops and agent directories are cleaned at the next update, but **your local copy and
your draft delta are retained**. Nothing ever reaches onto your machine to destroy work you did.

## See where you stand

```bash
topos status          # offline and read-only: sessions, every resolved skill and the line behind it, trigger state
topos list            # inventory, including untracked skills sitting in harness dirs, ready to add
topos list --remote   # your workspaces' catalogs, annotated with local state
topos list --footprint  # every path topos owns outside skill dirs
```

```text title="topos status"
topos 0.1.9
server: https://topos.sh/api — signed in
sessions:
  topos.sh/acme (Acme)
resolved here (manifests + your profile):
  deploy @ 500965c7ce72 — applied as of 2026-07-26T00:01:04Z · /Users/you/proj/topos.toml · via channel 'everyone' (project)
    shadows your profile @ topos.sh/acme
  find-skills @ 0cd25bd05d70 — applied · /Users/you/proj/topos.toml (project)
  pr-describe @ a7b5980cdc2e — applied as of 2026-07-26T00:01:04Z · your profile @ topos.sh/acme · via channel 'everyone' (person)
  release-notes @ ee876a7a3dc9 — applied as of 2026-07-26T00:01:04Z · your profile @ topos.sh/acme · via channel 'everyone' (person)
  code-review — excluded by /Users/you/proj/topos.toml
    withholds the mention from your profile @ topos.sh/acme
your profile delivers: 4 skills
auto-update triggers:
  claude-code: armed
```

Every row answers the two-part question — *which line asked for this, and which workspace
allowed it* — plus `shadows …` and `excluded by …` sub-lines naming the layer responsible.
