Two ways in, same result.

<Tabs>
  <Tab title="Run it yourself">
    ```bash
    curl -fsSL https://topos.sh/install | sh
    ```

    Installs the `topos` binary to `~/.local/bin` — no sudo, no runtime dependencies. Check
    it:

    ```bash
    topos --version
    ```
  </Tab>
  <Tab title="Ask your agent">
    ```text title="Paste to your agent"
    Set up Topos for us: fetch https://topos.sh/agent and follow it. Our workspace: https://topos.sh/acme
    ```

    Your agent shows you the install command before running it, and it cannot approve the
    browser login on your behalf — that click stays yours. No workspace yet? Leave that part
    off.
  </Tab>
</Tabs>

<Tip>
  Self-hosting? Your server serves the same installer at `<your-origin>/install` and its own
  agent walkthrough at `<your-origin>/agent`.
</Tip>

## Platforms

| Platform | Supported |
|---|---|
| macOS — Apple Silicon and Intel | Yes |
| Linux — x86_64 and arm64 | Yes (static binary, any distro) |
| Windows | Inside [WSL2](https://learn.microsoft.com/windows/wsl/install) |

## What the installer does

- Detects your OS and architecture, downloads the release over TLS, and **verifies its
  sha-256** — a mismatch always refuses, never skippable.
- Verifies the release signature when the `minisign` tool is present (skipping is announced
  loudly, never silent).
- Stages the binary and swaps it into place atomically — a bad download can never replace a
  working install.
- Never edits your shell configuration; it prints a PATH hint instead.

| Env var | Flag | Effect |
|---|---|---|
| `TOPOS_VERSION` | `--version <tag>` | Pin a release tag instead of the latest |
| `TOPOS_INSTALL_DIR` | `--to <dir>` | Install somewhere other than `~/.local/bin` |
| `TOPOS_INSTALL_BASE_URL` | — | Point at a mirror or air-gapped proxy |

Prefer to verify a release yourself? Download from
[the releases page](https://github.com/topos-sh/topos/releases) and check any of:

```bash
shasum -a 256 -c SHA256SUMS
minisign -Vm topos-<target>.tar.gz \
  -P RWRsqhNImLJGum9BdXy1X/p7Dhr+xc0JQTyNPxaGW5emP/K/+828Euav
gh attestation verify topos-<target>.tar.gz --repo topos-sh/topos
```

Each signature is bound to one release and file, so an old signature cannot be replayed
against a newer tag.

## Keep the binary current

```bash
topos self-update            # replace the running binary
topos self-update --check    # only report whether a newer release exists
```

`self-update` verifies the signature and checksum — both mandatory — and touches no skills,
no workspace, no account.

<Warning>
  `topos upgrade` is deliberately ambiguous and refuses, naming both fixes: **`topos
  update`** refreshes your skills; **`topos self-update`** replaces the binary.
</Warning>

## Environment variables

| Variable | Default | Effect |
|---|---|---|
| `TOPOS_HOME` | `~/.topos` | Where topos keeps its state — logins, drafts, logs |
| `TOPOS_PLANE_URL` | `https://topos.sh` | The server a bare workspace name resolves against |
| `TOPOS_DEBUG=1` | off | Print full error chains to stderr (always logged to `~/.topos/log.jsonl`) |
| `TOPOS_NO_BROWSER` | unset | Never auto-open the login approval page |
| `TOPOS_UPDATE_TTL` | `300` | The silent update's throttle window in seconds (`0` disables) |
| `TOPOS_NO_UPDATE_CHECK` | unset | Disable the once-a-day "newer version" note |

## Docs first, binary later

The `topos` skill is downloadable as plain documentation, no binary required:

```bash
npx skills add topos-sh/topos
```

That places a `SKILL.md`, the command reference, and an `INSTALL.md` that walks your agent
through the real install. Later, `topos add topos` hands the downloaded copy to the CLI to
keep current.

## Uninstall

```bash
topos uninstall          # preview what would go
topos uninstall --yes    # apply
```

Removes the auto-update hooks and `~/.topos/`. It **never deletes a skill file** — everything
in your agent directories stays. The binary's own path is printed so you can remove it with
whatever installed it.
