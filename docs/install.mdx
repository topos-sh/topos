Two ways to do this, and they end in the same place.

<Tabs>
  <Tab title="Ask your agent">
    Paste this to the agent you already use:

    ```text title="Paste to your agent"
    Set up Topos for us: fetch https://topos.sh/agent and follow it.
    ```

    Already have a workspace address? Include it, and the agent logs the machine in too:

    ```text title="Paste to your agent"
    Set up Topos for us: fetch https://topos.sh/agent and follow it. Our workspace: https://topos.sh/acme
    ```

    Your agent shows you the install command before running it, and it cannot approve the browser
    login on your behalf — that step is yours.
  </Tab>
  <Tab title="Run it yourself">
    ```bash title="Terminal"
    curl -fsSL https://topos.sh/install | sh
    ```

    Installs the `topos` binary to `~/.local/bin`. No sudo, no runtime dependencies. Then check it:

    ```bash
    topos --version
    ```
  </Tab>
</Tabs>

<Tip>
  Self-hosting? Every Topos server serves the same installer at `<your-origin>/install` (and
  `/install.sh`), and its own agent walkthrough at `<your-origin>/agent`.
</Tip>

## Platforms

| Platform | Supported |
|---|---|
| macOS — Apple Silicon and Intel | Yes |
| Linux — x86_64 and arm64 | Yes (static musl, any distro) |
| Windows | Inside [WSL2](https://learn.microsoft.com/windows/wsl/install) — native Windows is refused with a pointer there |

## What the installer does

It detects your OS and architecture, downloads the release asset with its checksum manifest and
signature over TLS, prints the **expected and actual sha-256**, and refuses on a mismatch — that
check is never skippable. The minisign signature is verified when the `minisign` tool is present;
without it, the skip is announced loudly. The binary is staged and renamed into place atomically,
and its `--version` is run *before* replacing an existing install, so a bad download can never
displace a working one. It never edits your shell configuration — it prints a PATH hint instead.

Options, as an environment variable or a flag:

| Env var | Flag | Effect |
|---|---|---|
| `TOPOS_VERSION` | `--version <tag>` | Pin a release tag instead of the latest |
| `TOPOS_INSTALL_DIR` | `--to <dir>` | Install somewhere other than `~/.local/bin` |
| `TOPOS_INSTALL_BASE_URL` | — | Point at a mirror or air-gapped proxy |

Prefer to verify a release yourself? Download from
[the releases page](https://github.com/topos-sh/topos/releases) and check any of:

```bash
shasum -a 256 -c SHA256SUMS
minisign -Vm topos-<target>.tar.gz \
  -P RWRsqhNImLJGum9BdXy1X/p7Dhr+xc0JQTyNPxaGW5emP/K/+828Euav
gh attestation verify topos-<target>.tar.gz --repo topos-sh/topos
```

Each signature's trusted comment is bound to one release (`topos-sh/topos <tag> <file>`), so an old
signature cannot be replayed against a newer tag.

## Keeping the binary current

```bash
topos self-update            # replace the running binary
topos self-update --check    # only report whether a newer release exists
topos self-update --version v0.1.9   # pin a specific tag, including a downgrade
```

`self-update` verifies the minisign signature and the checksum, both mandatory — a failure is a
typed integrity error, never a fallback. It touches no skills, no workspace, and no account.

<Warning>
  `topos upgrade` is deliberately ambiguous and refuses, naming both fixes: **`topos update`**
  refreshes your skills; **`topos self-update`** replaces the binary.
</Warning>

## Client environment variables

| Variable | Default | Effect |
|---|---|---|
| `TOPOS_HOME` | `~/.topos` | The client state root — sessions, drafts, logs. Also how you run two installations against two servers on one machine |
| `TOPOS_PLANE_URL` | `https://topos.sh` | The default server a bare workspace name resolves against |
| `TOPOS_DEBUG=1` | off | Print each error's full source chain to stderr (it always lands in `~/.topos/log.jsonl`) |
| `TOPOS_NO_BROWSER` | unset | Never auto-open the login approval page |
| `TOPOS_UPDATE_TTL` | `300` | The quiet sweep's self-throttle window in seconds (`0` disables) |
| `TOPOS_NO_UPDATE_CHECK` | unset | Disable the passive once-a-day "newer version" note |

## No CLI yet, and want the docs first?

The `topos` skill is downloadable as documentation alone, with no binary:

```bash
npx skills add topos-sh/topos
```

That places `SKILL.md`, the generated command reference, and an `INSTALL.md` that walks your agent
through the real install. Afterwards, one explicit `topos add topos` hands the downloaded copy over
to the CLI to keep current.

## Uninstalling

```bash
topos uninstall          # describe what would go
topos uninstall --yes    # apply
```

Removes the auto-update triggers from your harness configs and deletes `~/.topos/`. It **never
deletes a skill byte** — everything in your agent directories stays where it is. The binary is not
self-deleted; its path is printed so you can remove it with whatever installed it.
