Two ways in, same result.

<Tabs>
  <Tab title="Run it yourself">
    ```bash
    curl -fsSL https://topos.sh/install | sh
    topos --version
    ```

    The `topos` binary lands in `~/.local/bin` — no sudo, no runtime dependencies.
  </Tab>
  <Tab title="Ask your agent">
    ```text title="Paste to your agent"
    Set up Topos for us: fetch https://topos.sh/agent and follow it.
    ```

    Your agent shows you the install command before running it, and it cannot approve the
    browser login on your behalf — that click stays yours. You pick (or create) the workspace
    in that browser approval, so there is nothing else to tell the agent up front.
  </Tab>
</Tabs>

<Tip>
  Self-hosting? Your server serves the same installer at `<your-origin>/install` and its own
  agent walkthrough at `<your-origin>/agent`.
</Tip>

## Platforms

| Platform | Supported |
|---|---|
| macOS — Apple Silicon and Intel | Yes |
| Linux — x86_64 and arm64 | Yes (static binary, any distro) |
| Windows | Inside [WSL2](https://learn.microsoft.com/windows/wsl/install) |

## What the installer does

- Downloads the release for your OS and architecture over TLS and **verifies its sha-256** — a
  mismatch always refuses, never skippable.
- Verifies the release signature when the `minisign` tool is present (skipping is announced
  loudly, never silent).
- Swaps the staged binary into place atomically — a bad download can never replace a working
  install.
- Never edits your shell configuration; it prints a PATH hint instead.

| Env var | Flag | Effect |
|---|---|---|
| `TOPOS_VERSION` | `--version <tag>` | Pin a release tag instead of the latest |
| `TOPOS_INSTALL_DIR` | `--to <dir>` | Install somewhere other than `~/.local/bin` |
| `TOPOS_INSTALL_BASE_URL` | — | Point at a mirror or air-gapped proxy |

Prefer to verify a release yourself? Download from
[the releases page](https://github.com/topos-sh/topos/releases) and check any of:

```bash
shasum -a 256 -c SHA256SUMS
minisign -Vm topos-<target>.tar.gz \
  -P RWRsqhNImLJGum9BdXy1X/p7Dhr+xc0JQTyNPxaGW5emP/K/+828Euav
gh attestation verify topos-<target>.tar.gz --repo topos-sh/topos
```

Each signature is bound to one release and file, so an old signature cannot be replayed against
a newer tag.

## Keep the binary current

```bash
topos self-update
topos self-update --check
```

The first replaces the running binary, the second only reports whether a newer release exists.
`self-update` verifies the signature and checksum — both mandatory — and touches no skills, no
workspace, no account.

<Warning>
  `topos upgrade` is deliberately ambiguous and refuses, naming both fixes: **`topos
  update`** refreshes your skills; **`topos self-update`** replaces the binary.
</Warning>

## Environment variables

| Variable | Default | Effect |
|---|---|---|
| `TOPOS_HOME` | `~/.topos` | Where topos keeps its state — logins, drafts, logs, and your own `topos.toml` |
| `TOPOS_PLANE_URL` | `https://topos.sh` | The server a bare `topos login` (or a bare workspace name) resolves against |
| `TOPOS_DEBUG=1` | off | Print full error chains to stderr (always logged to `~/.topos/log.jsonl`) |
| `TOPOS_NO_BROWSER` | unset | Never auto-open the login approval page |
| `TOPOS_UPDATE_TTL` | `300` | The silent update's throttle window in seconds (`0` disables) |
| `TOPOS_NO_UPDATE_CHECK` | unset | Disable the once-a-day "newer version" note |
| `TOPOS_HARNESS_REGISTRY_URL` | `https://topos.sh/harness-registry.toml` | Where the agent-directory table is refreshed from |
| `TOPOS_NO_HARNESS_REGISTRY_UPDATE` | unset | Never refresh that table — use only the one built into the binary |
| `TOPOS_HARNESS_REGISTRY=bundled` | unset | Read the table built into the binary and nothing else — skips both `~/.topos/harness-registry/` files for this run |

## Docs first, binary later

```bash
npx skills add topos-sh/topos
```

That places the `topos` skill as plain documentation — a `SKILL.md`, the command reference, and
an `INSTALL.md` that walks your agent through the real install. Later, `topos add topos` hands
the downloaded copy to the CLI to keep current.

## Uninstall

```bash
topos uninstall
topos uninstall --yes
```

The bare run previews. Applying removes the machine-wide auto-update hooks and `~/.topos/`; it
**never deletes a skill file** — everything in your agent directories stays. Run it inside a
checkout and that checkout's own auto-update hook entries go too; the preview names the files.
Other checkouts you set up keep their hook until you run `topos agents remove` there. The
binary's own path is printed so you can remove it with whatever installed it.

## Next

```bash
topos login
topos init -a claude-code
```

Pick your workspace in the browser, or create it right there, and one click connects the machine.
The second line names an agent Topos may use here, which is what turns auto-updates on for it;
Topos never touches an agent you did not name. Repeat `-a` for more, add `-g` for your
machine-wide skills, and `topos agents` shows the choice any time. Full walkthrough:
[Quickstart](/docs/quickstart).
