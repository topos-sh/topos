**Topos keeps every AI agent on your team working the same way.** One person publishes how
the team does something — the deploy checklist, the code-review standard, the release
process — and every teammate's agent has it at the start of its next session, along with
every update after that. Nobody sends a link, nobody re-explains the process.

And it goes both ways: when someone sharpens the process while working, the improvement
comes back to the team as a reviewable change instead of dying on their machine.

## The fastest way in

Paste this to the agent you already use — Claude Code, Cursor, Codex, any of them:

```text title="Paste to your agent"
Set up Topos for us: fetch https://topos.sh/agent and follow it.
```

The agent installs the CLI and walks you through login; the one browser approval is always
yours to click. Prefer the terminal? Two commands:

```bash
curl -fsSL https://topos.sh/install | sh
topos login https://topos.sh/<your-workspace>
```

## What using it looks like

<Steps>
  <Step title="Someone shares a skill">
    `topos publish pr-describe --yes` puts a skill folder in the workspace — one name, one
    version history, one current version for the team.
  </Step>
  <Step title="Everyone's agents receive it">
    Every machine logged into the workspace gets it automatically. Nothing for teammates to
    run, nothing to configure.
  </Step>
  <Step title="It stays current by itself">
    At the start of each agent session, the machine silently picks up whatever changed —
    verified byte-for-byte, and never written over anyone's local edits.
  </Step>
  <Step title="Improvements come back">
    Someone sharpens the skill while working and publishes again — directly, or as a
    proposal a teammate reviews first.
  </Step>
</Steps>

## Works with the skills you already have

A skill is a plain folder with a `SKILL.md` — the same open format Claude Code, Cursor, and
the [skills.sh](https://skills.sh) ecosystem already use. Nothing to convert: share the
folders you have, and import public skill repos directly:

```bash
topos add vercel-labs/skills -s find-skills
```

What Topos adds on top is **declarative**: a short `topos.toml` states what a project or a
person should have, and every machine converges on it — a lockfile for agent skills, kept
current automatically.

## Cloud or self-hosted

- **Topos Cloud** — [create a workspace](https://topos.sh) at topos.sh; your team's address
  becomes `topos.sh/<name>`.
- **Self-hosted** — the entire product is Apache-2.0 in
  [one repository](https://github.com/topos-sh/topos) and runs from one compose file; your
  address is your own domain.

Same code, same CLI — only the address differs.
