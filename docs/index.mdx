Paste this to the agent you already use — Claude Code, Cursor, Codex, any of them:

```text title="Paste to your agent"
Set up Topos for us: fetch https://topos.sh/agent and follow it.
```

It installs the CLI and walks you through login; the one browser approval is always yours to
click. By hand:

```bash
curl -fsSL https://topos.sh/install | sh
topos login
```

The browser opens to sign you in; pick your workspace there — or create it on the spot — and
one click connects. That machine now has everything the team gave you, and picks up every later
change on its own.

## What using it looks like

One person publishes how the team does something — the deploy checklist, the code-review
standard, the release process. The commands are built for agents to drive, so tell yours what
you want or run them yourself:

```bash
# Ask your agent: "Share our code-review skill with the team."
topos publish code-review --yes
```

The skill is the team's now: one name, one version history, one current version. Every
teammate's agent has it at the start of its next session — nobody sends a link, nobody
re-explains the process. Updates never overwrite local edits, so when someone sharpens the
skill while working they publish again and the improvement comes back to the team — directly,
or as a proposal a teammate reviews first.

## Works with the skills you already have

A skill is a plain folder with a `SKILL.md` — the same open format Claude Code, Cursor, and the
[skills.sh](https://skills.sh) ecosystem already use. Nothing to convert: share the folders you
have, and import public skill repos directly:

```bash
topos add vercel-labs/skills/find-skills
```

Applying that records a line in [`topos.toml`](/docs/topos-toml) — a short file stating what everyone
working in a project should have, which every machine then converges on. For what follows a
*person* around there is no file to write: connecting is the whole statement, and a page in the
browser shows what you have, why, and an off switch for anything you don't want.

## Cloud or self-hosted

- **Topos Cloud** — [create a workspace](https://topos.sh) at topos.sh; your team's address
  becomes `topos.sh/<name>`.
- **Self-hosted** — the entire product is Apache-2.0 in
  [one repository](https://github.com/topos-sh/topos) and runs from one compose file; your
  address is your own domain.

Same code, same CLI — only the address differs.
