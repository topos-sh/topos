`topos.toml` is the manifest: what the agents working in this folder should have. It is edited by
`topos add` / `topos remove`, and **hand-editing is fully supported** — comments and layout survive,
because the writer edits the document rather than rewriting it.

```toml
exclude = ["topos.sh/acme/noisy-skill"]   # top-level, above the tables

[skills]
"topos.sh/acme/code-review" = "*"                        # track current
"topos.sh/acme/deploy" = "9f2c…"                         # pinned to a 64-hex version digest
"github.com/vercel-labs/skills/find-skills" = "3aa01e2"  # external: pinned to a commit
"./tools/my-skill" = "*"                                 # a local folder in this repo

[channels]
"topos.sh/acme/channels/backend" = "*"

[placement]
"topos.sh/acme/code-review" = ".claude/skills"
[placement.kind]
skill = ".agents/skills"
```

## Where a manifest lives

| File | Scope |
|---|---|
| `<repo>/topos.toml` | The project. **Commit it** — it travels, so every teammate's agents get the same set |
| `<repo>/<subdir>/topos.toml` | A nested scope. Nearest wins when resolving |
| `~/.topos/topos.toml` | Your personal manifest. Unshared local entries only |

Create one with `topos init`, which writes exactly this header and never overwrites an existing file:

```toml
# topos.toml — the skills this project uses. Managed by `topos add` / `topos remove`;
# hand-edits are fine. `topos update` reconciles agents in this folder against it.
```

Your **per-workspace profile** is the third layer and is not a file — it lives on the server and
roams between machines. Edit it with `topos add -g` / `topos remove -g`, or in the browser.

Layer precedence and the `$HOME` guard: [Manifests and scopes](/concepts/manifests).

## `[skills]`

Keys are [references](/concepts/references); values are pins.

| Value | Meaning |
|---|---|
| `"*"` | Track `current` — take whatever the workspace says is current, silently |
| `"<64-hex>"` | Pinned to that exact version's bytes |
| `"<7–40-hex>"` | A GitHub commit, for an external reference |

```toml
[skills]
"topos.sh/acme/code-review" = "*"
"topos.sh/acme/deploy" = "9f2c1a8b3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f60718293a4b5c6d7e8"
"github.com/vercel-labs/skills/find-skills" = "3aa01e2"
"./tools/my-skill" = "*"
"/abs/path/to/skill" = "*"
```

<Note>
  **Workspace references track `current`; external git references are pinned by default.** There is
  no governance rail behind a third-party repo, so it behaves like a lockfile line.
</Note>

A hand-written pin is validated by exactly the same rules the CLI applies — a handwritten manifest is
no back door.

Path entries inside the repository are stored **relative** to the manifest; a path outside it is
stored absolute.

## `[channels]`

```toml
[channels]
"topos.sh/acme/channels/backend" = "*"
```

A channel reference expands to whatever that channel currently contains. **Channels take no pin** —
`"*"` is the only value.

## `exclude`

A top-level array of canonical references, above the tables.

```toml
exclude = ["topos.sh/acme/noisy-skill"]
```

An exclude subtracts an item that a **broader** layer provides — your profile, a channel, or the
baseline. It is the **only** form of negative state in Topos. Written for you by `topos remove` when
that is the right outcome, and the receipt says so.

Nearest wins: a project exclude beats a profile entry inside that project.

## `[placement]`

Optional. Pins where bundles land, so one location serves every agent regardless of harness.

```toml
[placement]
"topos.sh/acme/code-review" = ".claude/skills"   # per bundle

[placement.kind]
skill = ".agents/skills"                          # per kind — the default for all skills
```

Values are **project-relative directories**.

<Warning>
  A committed manifest may never place files outside its own checkout. Absolute values, `..` climbs,
  and symlink escapes are **ignored**, not honored.
</Warning>

Without `[placement]`, placement is logical: derived from which harnesses are detected. See
[How harness integration works](/harnesses/how-it-works#where-bytes-land).

There is deliberately **no personal or machine-local placement config** — that would reintroduce
invisible machine state.

## Canonical form

The CLI always writes the **canonical host-qualified** reference:

```
topos.sh/acme/code-review
topos.sh/acme/channels/backend
github.com/vercel-labs/skills/find-skills
```

You may *type* `@acme/code-review`; the host comes from the session that resolved it. That is why a
manifest read on any machine is unambiguous, including a teammate's machine logged into a different
set of workspaces.

## Committing it

Commit `topos.toml`. Do **not** commit the delivered skill directories — every landed project
placement is added to `.git/info/exclude` automatically, and your committed ignore files are never
touched.

```bash
git add topos.toml
git commit -m "Add the team's code-review skill"
```

A teammate who clones the repo and runs `topos update` — or just starts their agent, since the
session-start trigger runs it — converges on the same set, minus anything their seats do not entitle
them to.

## Validating

```bash
topos status     # the resolved table: which line won, from which manifest, and why
topos update     # reconcile against it
```

`status` is offline and read-only. It names the manifest behind every row, plus `shadows …` and
`excluded by …` sub-lines pointing at the layer responsible.
