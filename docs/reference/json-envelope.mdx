`--json` works on **every** verb, prints **exactly one envelope object on stdout**, and **never
prompts**. This is the surface an agent should drive.

Four rules cover almost everything an agent needs:

1. **Use `--json` on every verb**, and read the envelope rather than parsing prose.
2. **Follow `next_actions`** — each carries a complete `argv`.
3. **Describe once, then act.** Repeating a describe is never progress.
4. **Never route around a refusal** by hand-editing files or internal state. Read the error, run the
   named fix, retry once.

New to Topos entirely? Start at [Quickstart](/quickstart) — the agent path is woven through it — or
fetch [`topos.sh/agent`](https://topos.sh/agent), the plain-text setup walkthrough every Topos server
serves at `<origin>/agent`.

## The envelope

```json
{
  "schema_version": 1,
  "command": "publish",
  "ok": true,
  "data": { },
  "warnings": [],
  "next_actions": [
    {
      "code": "APPLY_DESCRIBED",
      "argv": ["topos", "publish", "deploy", "--to", "everyone", "-m", "tidy up", "--yes"],
      "mutates": true,
      "needs_network": true
    }
  ]
}
```

| Field | Notes |
|---|---|
| `schema_version` | Always `1` |
| `command` | The verb. `pull` always reports as `update` |
| `ok` | Whether the operation succeeded |
| `data` | The per-verb payload |
| `warnings` | Strings. Non-fatal |
| `next_actions` | Machine-actionable steps — see below |
| `receipt` | Present on every terminal operation, including failures |
| `error` | Present only when `ok` is `false` |

### `error`

```json
{
  "code": "PUBLISH_BLOCKED",
  "outcome": "CONFLICT",
  "retryable": false,
  "affected": { "skill": "deploy", "workspace": "acme" },
  "context": { "message": "your copy is behind the team's current" },
  "next_actions": [ { "code": "REBASE_AND_RETRY", "argv": ["topos", "update", "deploy"] } ]
}
```

`outcome` is a **closed** set — safe to branch on:

`OK` · `CONFLICT` · `DIVERGED` · `DENIED` · `UNAVAILABLE` · `AMBIGUOUS_NAME` · `RETRYABLE_FAILURE` ·
`PERMANENT_FAILURE` · `NEEDS_REVIEW`

`code` is a finer-grained string. **Treat an unrecognized code as its `outcome`** — the vocabulary is
additive.

## `next_actions`

```json
{
  "code": "LOGIN_WORKSPACE",
  "argv": ["topos", "login", "<workspace-address>"],
  "mutates": true,
  "needs_network": true,
  "needs": ["workspace-address"]
}
```

| Field | Meaning |
|---|---|
| `code` | An **open vocabulary**. Execute an unknown code via its `argv` — never reject it |
| `argv` | A complete argv array |
| `needs` | Placeholder names still to substitute. **Absent or empty means runnable as-is** |
| `mutates`, `needs_network`, `risk_note` | Safety metadata. **Absent means unknown** — not "safe" |

Every error whose prose names a concrete command carries that command **structurally** here too, so
an agent never has to parse English to find the fix.

Known codes include `PROPOSE_PUBLISH`, `REBASE_AND_RETRY`, `RESOLVE_DIVERGED_DRAFT`,
`APPLY_WAITING_UPDATE`, `DISAMBIGUATE_NAME`, `REQUEST_ACCESS`, `RETRY`, `CONTACT_ADMIN`,
`FETCH_FULL_DIFF`, `NEXT_PAGE`, plus `APPLY_DESCRIBED`, `UNDO`, `LOGIN_WORKSPACE`, and others.

## Exit codes

| Code | Class | What to do |
|---|---|---|
| `0` | Success | Continue |
| `1` | Domain refusal or failed operation | Read `error`. `outcome` + `retryable` separate a refusal from a transport fault. Run the named fix, retry **once** |
| `2` | Usage error — unknown flag, missing argument, mutually-exclusive flags | Fix the command. Do not retry unchanged |

**The classes are the contract; the specific numbers are the implementation's.**

<Warning>
  A bare `topos` with no verb is exit `2` when piped or under `--json`. On a terminal it renders the
  status snapshot instead. Always name a verb in automation.
</Warning>

`topos update --quiet` exits `0` on an auth or network blip, deliberately, so a session start never
fails.

## Consent and two-phase verbs

Topos asks first when an act **reaches your team, loses local work, or trusts something new**. Those
verbs are two-phase: a bare run **describes** and writes nothing; `--yes` applies in one shot and the
describe hands you the exact `--yes` argv.

Everything else applies immediately and prints an **undo-led receipt**, where `--yes` is an accepted
no-op.

| Verb | Behavior |
|---|---|
| `publish` | **Two-phase.** The describe does not adopt an untracked source |
| `review <target> --approve\|--reject\|--withdraw` | The **verdict flag is the apply**. A target with no verdict is the describe |
| `revert` | **Two-phase.** `--yes` also acknowledges a byte-level no-op |
| `protect` | **Two-phase** |
| `invite <emails…>` | **Two-phase.** A bare `invite` with no addresses is a read |
| `update --reset` | **Two-phase**, loss-led. Refuses without a named skill |
| `uninstall` | **Two-phase** |
| `remove` | **Two-phase only when loss is real** — a draft ahead, or a permanent local delete |
| `add` | Immediate, except the keep-as-yours fork |
| `init`, `login`, `logout`, `update`, `list`, `diff`, `log`, `status`, `auth status`, `self-update` | Immediate |

<Warning>
  **`--yes` is parsed on every verb**, and is a no-op where the act applies immediately. Two places
  where it means nothing at all: `review` (the verdict flag is the apply) and any already-immediate
  verb.

  Some `--yes` help strings still read *"Parses today; the two-phase describe lands later."* That
  sentence is stale for `publish`, `review`, `protect`, `invite`, `update --reset`, `revert`, and
  `uninstall`, which all describe today. Trust this table.
</Warning>

**Describe once, then act.** Repeating a describe is never progress.

## Pagination and budgets

| Flag | Terminal default | `--json` default |
|---|---|---|
| `list --limit` | unlimited | **50** per bucket |
| `log --limit` | unlimited | **20** |
| `diff --max-bytes` | unlimited | **65536** (64 KiB) |
| `review --max-bytes` | unlimited | **65536** (64 KiB) |

`0` means no cap everywhere. Diffs truncate at **file boundaries**, marking omitted patches and
emitting a `FETCH_FULL_DIFF` next action; row caps emit a truncation marker and `NEXT_PAGE`.

## Other machine-surface behavior

<AccordionGroup>
  <Accordion title="login never blocks when piped">
    A piped run without `--wait` prints the approval URL, polls once, and exits `0`. Re-run to poll.
    `--json` never blocks and never opens a browser. `--wait <seconds>` is the explicit opt-in.
  </Accordion>
  <Accordion title="status is offline and read-only">
    It dials nothing, arms nothing, and repairs nothing — it dispatches ahead of any recovery work.
  </Accordion>
  <Accordion title="Errors are redacted on the surface">
    The safe message is in `error.context.message`. The full source chain always lands in
    `~/.topos/log.jsonl`, and goes to stderr with `TOPOS_DEBUG=1`.
  </Accordion>
  <Accordion title="update --quiet overrides --json">
    Stdout stays near-silent; errors go to stderr. That is what the session-start trigger runs.
  </Accordion>
  <Accordion title="Idempotency">
    Every write rides an operation log, so the same operation replays byte-identically after a crash
    or a retry.
  </Accordion>
</AccordionGroup>
