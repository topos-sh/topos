<AccordionGroup>
  <Accordion title="Bundle">
    A directory of files with a `SKILL.md` at its root — the unit of sharing and of trust. Today the
    only bundle **kind** is `skill`. See [Skills and bundles](/concepts/skills).
  </Accordion>
  <Accordion title="Channel">
    A named, curated **set of bundles**. Nothing else — no membership roster, no versions, no review.
    People carry a channel by referencing it. Every workspace is born with `everyone`, the baseline.
    See [Channels](/concepts/channels).
  </Accordion>
  <Accordion title="current">
    The one movable pointer per skill: what the team is on. It only ever *moves*, so every change is
    invertible. Moves are compare-and-set against a generation counter.
  </Accordion>
  <Accordion title="Curated / open (channel mode)">
    Who may edit a channel's references. `open` = any member (the default); `curated` = reviewer or
    owner. Set with `topos protect`.
  </Accordion>
  <Accordion title="Demand ∩ entitlement">
    The whole rule. **Demand** is what the manifests covering your directory ask for; **entitlement**
    is what your seats allow. An agent gets the intersection. See [How Topos works](/concepts/overview).
  </Accordion>
  <Accordion title="Describe / apply (two-phase)">
    A bare run of a reaching or lossy verb *describes* what would change and writes nothing; `--yes`
    applies it in one shot. Everything else applies immediately with an undo-led receipt.
  </Accordion>
  <Accordion title="Draft">
    Your local edits ahead of the version last applied. One edited copy **is** the draft. Updates
    merge around it and never destroy it.
  </Accordion>
  <Accordion title="Exclude">
    A line in a manifest that subtracts an item a broader layer provides. **The only form of negative
    state in Topos.**
  </Accordion>
  <Accordion title="everyone">
    The default channel, born with every workspace and implicitly part of every member's profile —
    the baseline. It cannot be renamed, deleted, or dropped from a profile; individual items can be
    excluded.
  </Accordion>
  <Accordion title="Governance transfer">
    What a landed `publish` of a local folder does: the workspace takes over deciding what `current`
    is, and your manifest's path line becomes the workspace reference. See
    [Publish a skill](/motions/publish-a-skill#governance-transfer--the-default).
  </Accordion>
  <Accordion title="Harness">
    An agent runtime — Claude Code, Cursor, Codex, and 70+ others. To Topos, a harness is *which
    directories to read and write* plus *when an update check fires*. See
    [How harness integration works](/harnesses/how-it-works).
  </Accordion>
  <Accordion title="Manifest">
    A `topos.toml` file — the lines asking for skills. Four layers: this folder, ancestor folders,
    your server-stored profile, and your personal manifest. **Nearest wins.** See
    [Manifests and scopes](/concepts/manifests).
  </Accordion>
  <Accordion title="Profile">
    Your per-workspace manifest, **stored on the server**. It roams to every machine you log in and is
    editable in the browser. Edited with `topos add -g` / `topos remove -g`.
  </Accordion>
  <Accordion title="Proposal">
    A candidate version awaiting a verdict — a version `current` has not moved to. Opened by
    `--propose`, or automatically when a member publishes to a `reviewed` skill.
  </Accordion>
  <Accordion title="Protection (open / reviewed)">
    Whether a member's publish moves `current` directly (`open`) or becomes a proposal (`reviewed`).
    A skill inherits the workspace default unless it pins its own.
  </Accordion>
  <Accordion title="Reference">
    How you name something. Shape-determined: `code-review`, `@acme/code-review`,
    `@acme/channels/backend`, `topos.sh/acme/code-review`, `owner/repo`, `./path`. See
    [the grammar](/concepts/references).
  </Accordion>
  <Accordion title="Roster">
    The workspace's membership. **The roster is the lock** — links carry no authority, so there is
    exactly one kind of link.
  </Accordion>
  <Accordion title="Seat">
    Membership in a workspace: read access to its whole catalog, at git-clone-level trust. Roles:
    member, reviewer, owner.
  </Accordion>
  <Accordion title="Session">
    One person × one workspace × one installation, minted by `topos login`. Revocable from both
    sides. Replaced the older per-device model. See
    [Workspaces, seats, and sessions](/concepts/workspaces-and-sessions).
  </Accordion>
  <Accordion title="Skill">
    The dominant bundle kind: `SKILL.md` plus scripts and reference docs. One identity, one version
    history, one movable `current`.
  </Accordion>
  <Accordion title="Staleness window">
    How long a session may go without reporting before the sessions page calls it *stale*. A workspace
    setting; 7 days by default. Stale means **unconfirmed, not wrong** — an idle machine reads stale.
  </Accordion>
  <Accordion title="Sweep">
    A full `topos update` run: resolve the layers, land what changed, retire what nothing demands,
    report the applied state. `--quiet` is the throttled version the session-start trigger runs.
  </Accordion>
  <Accordion title="Trust rail">
    The two-part answer to "why does this agent have this?" — which manifest line asked, and which
    seat allowed. `topos status` prints it.
  </Accordion>
  <Accordion title="Vault (plane)">
    The byte-custody service: content-addressed versions and `current` pointers. Identity-free, with
    one caller (the app) over an internal lane, and **no public port**. You will mostly never think
    about it.
  </Accordion>
  <Accordion title="Version">
    The sha-256 of a bundle's exact bytes. `<skill>@<hash>` pins exactly those bytes. Nothing is
    normalized.
  </Accordion>
  <Accordion title="Workspace">
    The org: one roster, one address, one catalog, one audit trail. `https://topos.sh/acme` on the
    cloud, or your own origin self-hosted.
  </Accordion>
</AccordionGroup>

## Retired words

Older material may still use these. They no longer describe the system:

| Retired | Now |
|---|---|
| `follow` / `unfollow` | `topos add` / `topos remove` (with `-g` for person scope) |
| **device**, device link, fleet | **session**, and the *Sessions* page |
| Channel *membership* | People carry a channel by referencing it in a profile or manifest |
| Device exclusions, opt-out rows, detachment records | A single `exclude` line in a manifest |
| `topos channel add` / `remove` | Curate in the browser, or `topos publish --to` |
| `auth login` / `auth logout` | `topos login` / `topos logout` (`auth status` remains) |
| `topos upgrade` | `topos update` for skills, `topos self-update` for the binary |
| "currency" | auto-update, delivery, update |
